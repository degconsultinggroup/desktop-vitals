# Desktop Vitals v2

## Goal

Full visibility of what's happening on this machine, fit for the agent era. A person looks at one window and knows what's going on: which agents are working and on what, what's running that they started, whether it's OK, and what it costs. Their own agent can install it, configure it, and read it for them.

Make it a work of simplicity and beauty. Remove everything that doesn't serve the goal. Keep the liquid glass look.

## The look

Keep v0.1.0's glass exactly as a material: the Windows 11 acrylic frosted blur behind the window (`ApplyGlass`), the clear pane that thins toward the bottom, the sheen across the top, the rim that catches light at the top-left (`Theme`, around the "Glass:" and "Light catching a glass edge" comments), the 20px rounded pane, Segoe UI Variable Display/Text, and the dark palette. One glass pane instead of a stack of cards. Hierarchy comes from type weight, spacing, and the state dot, not boxes and lines. Calm when everything is fine. The eye goes straight to anything that needs the person.

## How it decides

No name lists, no folder conventions, no settings. Five facts Windows already knows. Research and prototypes: `audit/v2/grouping.md` + `tools/v2-proto/`, `audit/v2/agents.md` + `tools/v2-agents/`, `audit/v2/teardown.md`, `audit/v2/deletions.md`.

1. **Who started it.** Walk the parent chain to the launcher, PID-reuse safe (the parent must be created before the child). A terminal, editor, Explorer, a non-Microsoft/non-vendor scheduled task, or Startup → yours. Services tree / session 0 → not yours. When the parent has exited (common for supervised bots), fall back to facts 2–3: an image or script in a project folder under the user profile, long-lived → yours. Shell-host-launched packaged apps (sihost) are apps, not services.
2. **Where it lives.** The project is the nearest ancestor of the cwd, script, or exe holding .git, package.json, pyproject.toml, Cargo.toml, go.mod, or *.sln. A git worktree resolves to its main repo, and the branch shows. Installed apps (signed image under Program Files, AppData\Local\Programs, WindowsApps) are apps.
3. **What it's doing.** Listening ports (GetExtendedTcpTable) → server. VRAM per pid (existing counters) or mapped weight files → model runtime. Long-lived with periodic file writes → bot. No activity for 5 min → quiet. Exit → ended (0) or failed (non-zero). For scheduled tasks, last result != 0 → failed.
4. **What a model runtime has loaded.** Mapped files of same-user processes (VirtualQueryEx + GetMappedFileNameW). Name the model from the weight file, merge shards, count weights only. Fall back to -m/--model in the command line. Unloaded models on disk are one collapsed line.
5. **What an agent is doing.** Model from the command line. Repo and branch. The child process it's running now. Git progress since it started, read from .git directly, never by spawning git. Last action from its local session log: Claude Code `~/.claude/projects`, Codex `~/.codex/sessions`, Cursor CLI `~/.cursor/chats` via winsqlite3 read-only. Show only action kind + file name + age. Never prompt text, code, or output. Several sessions of one agent in one repo are one line with a count.

Display-name maps ("Claude Code", "Codex", "Cursor agent") apply last, from the command line, never from a bundled node.exe. An unknown agent still shows, as "node · repo-a".

Cost: compute provenance, project and kind once per pid when it first appears, and cache them. Each tick refreshes only CPU, RAM, VRAM, ports, and state. Target: ≤0.5% CPU and ≤80 MB live, a pass under 50 ms at 300 processes, zero work when off or minimized.

## The data contract

Engine and window meet at one model, and `--json` prints exactly that model:

```
Board { name, strip{cpu, ram_used_gb, ram_total_gb, gpu?, gpu_temp?, vram_used_gb?, vram_total_gb?, disk_free_gb, disk_total_gb},
        headline{text, needs_you},
        groups[{title, kind: agents|project|models|other|ended, things[Thing]}] }
Thing { id, name, kind: agent|server|bot|script|task|model|app|other, state: working|running|waiting|quiet|idle|failed|ended,
        project?, branch?, folder?, ports[], cpu, ram_mb, vram_mb, count, since, detail?, why, pinned }
```

`detail` is the second line ("editing install.ps1 · 3 commits", "failed 06:00 · next in 20h"). Every string passes through `Redact.Show`.

`DesktopVitals.exe --fixture board.json` renders a given Board instead of reading the machine. Combined with `--snapshot`, that gives deterministic screenshots for CI, the README and the window work. `tests/fixtures/board-dev.json` and `board-fresh.json` encode the two mocks above.

## Settings, for people and agents

Zero config. The only preferences are the PC name, renames, hides, and pins, stored in `%APPDATA%\DesktopVitals\prefs.txt`. `--name`, `--rename <id> <name>`, `--hide <id>`, `--pin <id>`, `--unpin <id>` and `--json` let an agent do everything a person can. On first run, an existing watch.txt/review.txt migrates once: labels → renames, @hide → hides, rules → pins.

## What goes

Per `audit/v2/deletions.md`: the eight cards (System grid, AI, Bots, Scripts, Starts with Windows, Scheduled, Pinned, Top apps), per-thread bars, watch.txt and its parser and @-directives, the review screen, kind tags, http/file `check:` rules, and the temperature file. README and watch.example.txt shrink to match. `src` ends shorter than v0.1.x, split by role: `src/App.cs` (entry, CLI, prefs), `src/Engine.cs` (facts → Board), `src/Window.cs` (glass + list), and `src/Native.cs` if needed. `build.ps1` compiles them all.

## Hard constraints

Read-only: never start, stop, or kill other processes. asInvoker, no admin. Network: loopback only. No telemetry. In-box csc, C# 5, no NuGet. Secret redaction everywhere. The #3 suites (smoke, accuracy, safety-runtime, stability, locale-perflib) stay green. Assertions on deleted UI move to the new model, and the commit says so. Copy rules (UI, README, AGENTS.md): no fine print or reassurance lines under buttons or headings, no subheadings that restate the heading. A section is a heading and its content. A button is just the button.

## For cloud agents: building without Windows

Cloud agents run on Linux and can't compile WPF. GitHub Actions is the build machine. Push your branch, and CI builds and runs every suite on windows-latest and windows-11-arm. Read results without auth from the public API: `GET https://api.github.com/repos/degconsultinggroup/desktop-vitals/commits/<sha>/check-runs`, then each run's `/annotations`. Every failing check in tests/*.ps1 must print a `::error::<check>: <detail>` line so it shows up as an annotation. Push small, wait for CI, fix, repeat. Never call a step done until CI is green on your branch. The coordinator also builds each push on a real dev box, reviews screenshots, and sends you follow-ups.

## Handoff from FOUNDATION

`src` is 2706 lines (App.cs 474, Engine.cs 1477, Window.cs 674, Native.cs 81). v0.1.0 was 3435.

Green on `7d5f87b`: https://github.com/degconsultinggroup/desktop-vitals/actions/runs/38632250634
`windows`, `windows-arm`, and `windows-stability` succeeded. `release` was skipped because this was not a tag. The windows job uploaded `board-dev` and `board-fresh`.

What is stable:

- One glass pane draws any Board: strip, headline, group titles, and thing lines (state dot, name, project, state text, detail). Live switch, Ctrl+Alt+P, snapshot, and redaction stay.
- The live engine fills a real board from the collectors it kept: process snapshot, script command lines and working directories, VRAM counters, Task Scheduler, and the model store. It emits project groups (scripts, plus tasks that share a script folder), one collapsed models line, and a separate pins group.
- `--json` prints that board. `--fixture board.json` draws the file instead of the machine. With `--snapshot`, it writes `vitals.txt` and `vitals.png`. `tests/fixtures/board-dev.json` and `board-fresh.json` are the two mocks above.
- Prefs are `%APPDATA%\DesktopVitals\prefs.txt`. `--name`, `--rename`, `--hide`, `--pin`, and `--unpin` work. An old watch.txt migrates once into hides and pins.

Where to plug in:

- ENGINE: add agents, quiet bots, ended work, and heavy other inside `Engine.Build`. The types are `Board`, `Strip`, `Headline`, `Group`, and `Thing`. Do not invent those groups until the facts exist. `TaskList.Ready` and `ModelScan.Ready` flip when a pass finishes. `Engine.ScansComplete` is both. Snapshot and `--json` wait for that signal, after a 2.5s minimum so the CPU sample has a delta, and they give up at 45 seconds.
- WINDOW: `VitalsWindow.ShowBoard` and `AddThing` are the plain renderer. The beauty pass can change type, spacing, and the state dot without changing the contract. Glass is the material already in `Theme` (`Glass:` and `Light catching a glass edge`). `--fixture` skips the machine read, so screenshots of the two mocks do not depend on the host.

Surprises:

- `using System.Windows.Shapes` makes `Path` ambiguous. Call sites say `System.IO.Path`.
- The strip says `Disk N GB free`, not `C:`.
- `since` is a display string such as `6m` or `2h 10m`, not a timestamp.
- The live board does not redact `folder`, so a click can still open it. `--json` runs every string through `Redact.Show`, including `folder`.
- JSON is `DataContractJsonSerializer` in `System.Runtime.Serialization.dll`. Optional strings (`project`, `branch`, `folder`, `detail`) and the optional doubles (`gpu`, `gpu_temp`, `vram_used_gb`, `vram_total_gb`) use `EmitDefaultValue=false`. `build.ps1` also references `System.Xml.dll` because those signatures mention `XmlReader`. The deserializer does not run field initializers, so the fixtures set `count` themselves, and a missing `ports` list stays null.
- There is no line-1 slot for an agent model name. In `board-dev.json`, `grok-4.7-high` is in `why`. `detail` is the second line.
- The window uppercases group titles. `vitals.txt` keeps the stored title, so `bots-repo` stays lowercase in the text file and paints as `BOTS-REPO`.
- The import headline is `Imported hides and pins from your old watch.txt. Change them anytime with right-click.` It is applied only after the task scan is ready, and the flag is cleared only after that line has been written to the snapshot or shown on the live window. If something needs you, `importNote=1` stays in prefs.
- Several models collapse to `N models on disk`. Pins are their own things. They do not replace script names.
- `Scripts.IsSystemPath` still skips `GetTempPath()`. Leave that. Smoke scripts live under TEMP and still showed up on the runners.
- The exe is a window app. Wait with `Start-Process -Wait`. The call operator returns before it exits.
- No gear menu, and no right-click menu. The Frontier URL is not in `src` (the smoke URL allowlist would reject it). Rename, hide, and pin are the command line flags.
- `cores-split` on windows-arm stays inconclusive. The per-thread bars are gone.
